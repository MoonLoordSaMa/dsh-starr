# QQ 连接与故障处理

0.1.3-pre.1 在 starr 内实现 OneBot 11 会话与媒体工具，使用 DSH 原生模型会话与角色服务。无需让模型生成额外桥接插件。QQ、B站和网页角色会话统一显示在 Starr-chat，保留各账号与对象的可见范围。

## 首次配置

1. 安装 starr 后进入 DSH 侧栏的 starr，打开新手调试。插件会自动注册 `starr-qqchat` 预设。
2. 按 SnowLuma 教程登录机器人账号，启用 HTTP 服务和正向 WebSocket 服务。填写两项端口，默认分别为 `3000`、`3001`。当前驱动仅连接 `127.0.0.1`。
3. 如果 SnowLuma 设置了访问令牌，在密码框填入相同值，再点击“检查协议与 QQ 登录”。不需要把令牌发给模型。无令牌服务可以留空。
4. 填写允许回复的私聊 QQ 号和群号，用逗号、空格或换行分隔。空名单不会对外回复；群聊默认仅被 @ 时回应。
5. 完成角色、人格、记忆库与备份目录。B站和媒体模型可跳过。在扩展感官步骤选择 DSH 已配置的聊天服务与模型，可主动运行模型诊断。
6. 只有勾选“完成向导后启用 QQ 自动回复”且完成向导，驱动才开始工作。以后在“与世界相连 → 对话”修改角色、端口、名单、模型、合并等待与启停。
7. 用允许名单中的账号发一条文字消息。页面显示真实收件和处理结果，实际 QQ 收到回复才算该账号的完整验收通过。

协议检查同时验证 HTTP 响应格式、QQ 在线状态和 WebSocket 握手，不发送消息。绿色“已连接”只表示消息通道连通，不能证明模型或平台发送已经成功。可启用重连历史补拉，前提是 SnowLuma 支持相应历史接口；补拉有上限且仍按消息编号去重，不能保证找回所有离线消息。接口失败会保留提示，不伪装成没有历史。

## 令牌

Windows 使用当前登录用户的数据保护接口（DPAPI）加密到运行目录的 `qq-token.dpapi`。原文不进入数据库配置、向导草稿、网页响应、角色提示词、模型工具或命令行。密码框留空保留已有值；填写新值可轮换令牌。此文件只能由对应系统用户解密，更换 Windows 用户或机器后应重新填写。

也可以在 DSH 的启动环境中设置 `SNOWLUMA_TOKEN`，或在高级选项指定其他环境变量名。环境变量优先于加密文件；更换文件令牌不会覆盖已有环境变量。其他操作系统目前采用环境变量方式，网页不会改为明文保存。媒体服务密钥仍沿用其独立的环境变量配置。

## 会话、工具与去重

- 每个登录账号、角色与私聊/群聊目标使用独立的 DSH Session；同一群内按群共享会话，私聊与群聊分开。重启按原会话编号恢复历史。
- QQ 会话使用选定的 DSH 服务与模型，保留角色人格、16 项核心工具及宿主允许的普通工具。群聊的有限分段回复默认可用；普通文字回复也按空行分条，单换行保留在同一条中。超过配置条数时合并尾段，不丢正文；私聊分段和其他平台动作按权限注册，执行时再次复核。群聊回复将引用和 @ 限定在首条，逐条发送并记录每条回执。普通未绑定会话不显示 starr 工具。
- 默认合并 1200 毫秒内的短消息，最多 12 条一批，合并等待可调为 200–5000 毫秒；同一对话串行，不同对话最多四个同时处理。首次回复后可等待同一对象补充一次，继续当前宿主回合而不再占用唤醒额度；思考期间到达的其他消息留给下一批。
- 平台事件按消息编号持久去重；发送前先写台账，只有有效消息回执或明确安静才算完成。同一批只能成功发送一次，模型最终正文不会再次转发。
- 断线后退避重连；模型失败自动尝试最多三次。重试复用批次，不把完整用户文本反复添加为新经历。
- 暂停、修改连接或更换角色会中断旧批次。历史队列再次处理前重新核对账号与允许名单。多个宿主不能同时占用同一运行目录的 QQ 驱动。

群聊戳一戳由 OneBot 通知事件接入，不再只接收普通消息；必须戳当前机器人且来自已授权群。重复事件不会触发重复回复。SnowLuma 私聊通知优先以 sender_id 识别发起人。

## 状态与处理

| 状态或错误                   | 含义与处理                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| 令牌不匹配                   | HTTP 返回 401/403，确认 SnowLuma 和 starr 的令牌一致；检查环境变量是否覆盖         |
| QQ 未在线                    | 服务可达，但机器人未登录；先在 SnowLuma 登录                                       |
| WebSocket 未连接             | 检查正向服务端口、令牌和服务状态；单有 HTTP 端口不够                               |
| 模型繁忙、认证失败、额度不足 | 查看 DSH 模型服务，等待、重新登录或改用已配置模型；不是 SnowLuma 端口问题          |
| 模型未调用回复工具           | 模型回合结束却没有显式回复或安静；确认选用支持工具调用的模型                       |
| 明确失败                     | 有确定的拒绝或模型失败，可点击“重试失败消息”；旧授权已移除的队列仍不会发出         |
| 发送待核对                   | 请求可能送达，但回执缺失或发送时进程中断；先在 QQ 核对，插件不会自动或批量手动重发 |
| 运行目录已被占用             | 同一数据目录已有另一个 QQ 驱动；关闭重复宿主，勿直接删除正在使用的锁               |

图片和语音先保留未理解的占位；模型实际调用当前会话的图片或听写工具成功后才取得内容。媒体连接在“TA 的五官”配置；独立模型、密钥和错误各自隔离，配置不全时返回明确原因。附件仅接受受限 QQ 图片/音频域名，不跟随重定向，不让模型传入本机路径。

表情工具支持本角色表情查询、发送、从实际收件收藏与备注。语音工具使用所选 TTS 生成音频后发送。翻唱要求当前会话工具授权和唱歌页的 bot 授权，同时需要已导入音源、参考音色和可用转换服务。分条发送逐条确认，已经成功的前缀不会整组重发；回执不明时停止。任意文件发送和按情绪自动主动外发尚未接入。

## 验证边界

自动化测试使用独立合成角色、模拟协议与失败场景；联调使用真实 DSH 0.2.1-rc.5，模型和 OneBot 均为本地测试服务。它验证会话创建/恢复、工具作用域、人格注入、去重与消息回执链路。用户真实账号、真实聊天模型和 QQ 实际送达需在用户完成令牌配置后验证；不将本地模拟回执描述为真实 QQ 已恢复。
