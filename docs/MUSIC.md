# QQ点歌与统一曲库检索

QQ与B站属于同一角色的不同会话，公开音乐检索直接调用共享平台服务，不需要先让另一个平台的角色回复。`starr_song_list`只列本角色已经导入的曲库；找网络音乐使用`starr_song_search`。

## 从QQ需求到SVC翻唱

1. `starr_song_search({q:"歌名 歌手",platform:"all"})`汇总本角色曲库、B站视频与网易云曲目，也可指定`local`、`bili`、`netease`。每个平台独立返回结果或故障原因，不因一个平台不可用清空全部结果。
2. 本地曲库有合适音源时直接使用编号。网络候选调用`starr_song_source({platform:"netease",id:"歌曲编号"})`或`{platform:"bili",id:"BV号"}`。旧版`{bvid:"BV号"}`继续支持。
3. 插件读取实际可播放音频，经FFmpeg裁剪为45秒内WAV，写入当前角色附件区的曲库目录，保存来源链接并按音频内容去重。返回`sourceId`，模型无需接触或拼接本机文件路径。
4. QQ调用`starr_qq_sing({sourceId})`：插件在内部把编号解析为本角色文件，交给已配置SVC及默认参考音色，生成45秒内翻唱后发到当前可信QQ对象。没有平台发送工具的会话可用`starr_sing`只生成，不声称已经发送。

默认优先高潮/副歌：B站先搜索歌名加“高潮”，没有结果才回到普通搜索，标题标注高潮或副歌的候选优先。网易云保持原曲检索，在入库时尝试读取时间歌词，用多次重复的连续歌词定位副歌候选。该方法提供文字依据，不等同于音乐结构或听感高潮识别；没有可靠依据就从开头截取并明确提示。可传`segment:"opening"`改用开头，或传`startSeconds`指定实际起点；起点和定位依据持久保存在曲库，网页可查看。

## 配置

在“五感声色→弦歌不辍→QQ找歌与翻唱授权”集中查看：

- `sing.search.netease`默认开启，公开检索不需要另搭网易云API服务或填写API key。
- `bili.actions.allowBot`允许角色查询B站公开资料；B站服务仍需要有效登录。
- `sing.source.allowBot`允许角色保存B站或网易云网络音源，默认关闭；搜索不依赖这个入库开关。
- `sing.allowBot`允许角色生成翻唱。
- `chat.tools.singing`允许向当前QQ对象发送翻唱。

另外需要有效的`sing.mode`、本地SoulX配置和`sing.referenceId`。本地模型继续遵守全局互斥与5分钟闲置卸载。上述授权不会由角色自动开启；管理员在网页主动搜索和确认入库，不会顺带启用bot权限。

网页“循声拾曲”与QQ使用同一服务，能搜索、查看原曲页面、导入片段并选为翻唱音源。曲库显示来源，失败会保留明确原因。

## 平台边界

网易云通过平台公开接口检索并读取平台返回的音频地址。搜索命中不代表可取音频；版权、会员、付费、地区、试听或风控限制均可能让入库失败。受限结果不被解锁，不自动转接第三方下载站。公开接口未来变动也可能影响可用性。

B站媒体读取会从同一官方响应中选择符合下载约束的标准HTTPS主地址或备用地址。特殊端口和P2P地址不会被自动放行，避免首选地址不可用时忽略有效备用CDN。

本轮没有替用户在真实QQ或B站发布测试内容。真实网络检索、文件入库、合成SVC协议和模拟QQ发送分别验证，具体结果以交付记录为准。
