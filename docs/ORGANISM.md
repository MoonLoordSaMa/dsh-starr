# 心理、身体、情绪与目的

本模块是角色的虚拟状态模拟。它保持经历、感受与行为倾向的连贯性，不宣称生物学精确性、真实激素浓度或真实意识。

## 因果链

经历 → 身体与心理 → 情绪余韵与虚拟调节 → 需求／欲望 → 候选目的 → 条件评估 → 交由获授权的宿主执行。

时间只用于演化、作息和限流，不生成“每隔一段时间必须说话”的任务。当前独立版已经实现到目的评估与保存；DSH 事件订阅、模型自主调用及平台执行仍需宿主联调。

## 状态与情绪

统一定义在 `src/starrcore/organism.ts`，前后端共用。身体包括精力、睡意、饥饿、口渴、疲劳、舒适；心理包括愉悦、唤醒、紧张、社交意愿、安全感、好奇、孤独、受挫、信心、刺激负荷，数值均为 0–100。

兴奋驱动、安定、联结、压力、警觉与睡眠倾向由原始状态推导，界面放在高级展开区。它们是虚拟调节量，不使用医学单位。

18 种情绪可以同时存在：欣喜、安宁、亲昵、感激、好奇、期待、得意、释然、低落、焦虑、害怕、生气、挫败、孤独、无聊、羞怯、倦意、犹疑。各强度独立，不强制相加为 100；高愉悦不会将焦虑或挫败归零。标签概括主要感受，颜色、流速、扰动和图例来自同一份情绪快照。

流场默认显示八种较强的非零感受；“全部感受”显示当前所有非零感受，最多十八种。全览时减少每种感受的装饰线数量，保留每种流束的独立节律。关闭或移出视口时暂停，减少动态保留静态表达。

## 经历与持久化

经历类型：交谈、有所完成、遭遇挫折、歇息片刻、好好吃饭、喝一口水、遇见新事物、感到被理解、应接不暇、不安、安抚。类型对应明确的状态变化及情绪余韵；强度决定作用幅度。吃饭和休息不能由评估器假装已经发生。

`POST /api/characters/:id/experiences` 接收 `revision`、`eventKey`、`kind`、`intensity`、`evidence`。状态更新与审计在同一事务内；相同事件重试返回原结果，同编号异内容拒绝，过期修订拒绝覆盖。工具调用的来源绑定到可信宿主会话，角色编号不取自模型输入。

原始状态保存 `_updatedAt` 与 `_affect`；公开读取返回派生快照、情绪余韵及观察时间。读取不写库、不自动完成目的、不产生平台动作。每次实际事件提交前投影经过的时间，离线演化最多六小时；倒退时钟不反向累积。旧版状态缺失新增维度时补默认并初始化时间锚点。

手动调节只提交白名单原始字段；派生对象、凭据与权限不能通过状态回写。情绪名称保留兼容输入，显示与行为以派生向量为准。

## 欲望与目的

十种驱动力：休憩、补给、安全、亲近、探索、表达、成就、独处、秩序、玩乐。每项返回压力、依据、候选标题、行动类别；它们是倾向，并非必须执行的命令。

`GET /api/characters/:id/intentions` 结合当前状态、主动性开关、精力、社交意愿、作息时区、安静时段、外部行动冷却和约定时间评估。孤独与不愿社交可同时存在；低精力时优先休憩。外部动作在尚无已验证宿主执行器时始终等待，不因评分高而发送消息。

评估只读，不无限向数据库添加候选。用户或模型显式选定后，通过 `starr_goal_create` 保存，附带 `drive`、`action`、`external`。目的表安全补充 JSON 元数据列，保留原有目的。完成或取消均由显式操作记录；不伪造外部成功回执。

## 宿主工具

新增 `starr_experience_record` 与 `starr_intention_evaluate`，原八项保留，共十项。前者用于记录有依据的经历，后者用于读取可解释的行动倾向。宿主应先完成可信角色绑定，在适当会话事件后记录经历，再由模型参考状态提出、保留或放下目的；没有急切需求可以安静。

角色人格仍约束表达与偏好；虚拟状态为表达提供连续背景，不取代模型的语境判断。没有将整个心理引擎或冗长状态文本重复注入每轮聊天。
