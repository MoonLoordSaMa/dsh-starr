# DSH 接入

实现依据为本机 DSH 0.2.1-rc.5 的 `ctx.tools.register(definition)`、`exec.agent.id` 和插件卸载生命周期。官方主分支核对版本 0.2.2-alpha.2 尚未作为真实安装验收目标；本仓库没有臆造 super-agent SDK。

入口 `dsh-starr` 导出 Cordis 插件 `starrcore`，依赖宿主 `tools` 服务。宿主配置示例：

```yaml
- id: starrcore
  name: dsh-starr
  config:
    dataRoot: "<与独立控制台相同的新运行数据目录>"
    sessionBindings:
      "<可信宿主 Agent/Session ID>": "<控制台已有角色的稳定 ID>"
```

此配置示例不包含个人会话或凭据。插件包提供 `dsh.client` 声明及 `./client` 导出，复用宿主 React 和原生扩展槽位。客户端在 `sidebar.panellist` 注册顺序为 20 的星形入口，并在 `main` 注册对应的 `starr` 面板。入口默认位于“自动化任务”和“更多”之间，固定与取消固定沿用 DSH 的原生行为。

当宿主提供 `webServer` 和 `connection` 服务时，插件按需挂载 `/starr/` 控制台。静态资源、接口、图片与音频都使用同一挂载前缀。控制台与 16 项工具共用同一个 `StarrStore`，无需额外监听端口、启动独立服务或复制角色数据。接口复用 DSH 原生登录校验，再检查请求地址和来源。控制台仅允许同源页面及 DSH 桌面应用内嵌，独立预览仍禁止嵌入；插件卸载会移除路由和工具。没有网页服务的宿主继续提供工具。

更新原先没有 `dsh.client` 的安装副本后，需要完全退出并重新打开 DSH，让宿主重新读取包元数据。若连接失败，主面板显示具体的恢复提示和“重新连接”按钮。

`sessionBindings` 是管理员为普通宿主会话显式指定角色的可选配置。插件不再全局注册角色工具：普通未绑定会话不显示这 16 项工具，也无需为了正常聊天绑定角色。只有列入映射的会话才在自身作用域取得工具；模型不能通过工具参数选择另一个角色。会话创建、已有会话加载、销毁以及空会话预设切换均同步安装或移除对应工具。切到 `starr-qqchat` 后使用该预设的角色绑定，避免叠加普通会话的绑定。

16 项工具共用同一个业务服务：记忆写入、搜索、全文、关联，会话接续，状态读取与修改，经历记录、目的评估与创建，配置读取与受限修改，用语查询与提交，曲库查询与翻唱。经历来源固定为可信会话，目的评估只提出倾向，不自动执行。详细机制见 `ORGANISM.md` 和 `V013.md`。

工具注册契约测试验证全局与普通会话不暴露角色工具、可信绑定、拒绝跨会话调用、实际业务调用和卸载注销；界面接入测试另行验证路由注销、同库读取、未登录拒绝及跨站来源拒绝。真实 DSH 0.2.1-rc.5 的作用域与预设切换、网页宿主侧栏与点击流程的验证记录见 `VERIFICATION.md`。桌面应用重启后的界面仍需在用户当前实例确认。

插件现在使用宿主 `agentPresets.register` 自动注册 `starr-qqchat`，不改默认预设、不写宿主安装文件、不覆盖同名预设。新会话菜单显示“Starr-chat · 角色会话”。`./qq-session` 子插件在会话作用域注入人格与 16 项业务工具；角色从管理员已完成的新手调试中取得，再按真实 `exec.agent.id` 固定保存。已有 QQ 会话不会跟随之后的默认角色选择而换人。没有完成新手调试的会话会明确报错。

此预设保留继承的搜索、浏览器、视觉和平台等普通工具，仅通过宿主管理操作约束拦截已知终端和宿主配置工具，DSH 原生 read/write/edit/glob/grep/read_image 正常保留。管理员可用 `managementTools` 补充其他管理工具名称；该列表不能代替宿主对第三方工具的实际权限管理。普通 DSH 管理会话不受 QQ 预设的约束。

`starr_config_update` 不受这层管理工具约束。用户在权限页开启 `permissions.botConfig` 后，bot 可小幅调整统一定义中标注的字段，包括记忆召回、目的冷却、说话速度、部分情绪和兴趣偏好，需要当前修订号并留下配置审计。完整白名单与范围见 `CONFIGURATION.md`。它不能改变路径、连接、凭据、角色绑定或自身授权。

客户端通过真实 `shell.overlay` 槽位提醒首次使用，点击后由宿主 `layout.selectPanel("starr")` 打开控制台；完整流程见 `ONBOARDING.md`。完成向导后，仅在管理员勾选启用且所需配置完整时启动 QQ 驱动；不会启用 B站外发。不加载旧 qq-chat-v1/v2 引擎。

在宿主提供 `agents` 和 `agentPresets` 时，插件直接对接本机 OneBot 11 HTTP/正向 WebSocket。每个登录账号、角色与私聊/群聊目标创建独立 Session，通过 `agents.create/resume`、`followup` 和 `whenIdle` 使用 DSH 原生回路。QQ 会话模型来自管理员在 starr 选择的 DSH 服务与模型，不改变全局默认值。平台工具只注册到平台专用会话，并按角色开关决定是否提供历史、等待、收尾、分条、图片、听写、表情、语音和翻唱；默认配置下 QQ 为 16 项核心工具与 9 项平台工具。手动新建角色预设会话不会凭空取得平台收件目标。

B站会话、资料阅读与文字动态，以及定时日记与整理，均使用同一角色预设和 DSH 原生 Agent 回路；每次模型请求仍检查账号、会话范围、当前授权和预算。平台驱动、任务驱动和控制台共用媒体服务管理器，避免相同角色启动重复本地模型进程。

收件与批次持久化、平台消息去重、发送台账和进程独占锁均在角色代码之外的运行目录；同一批次只有真实消息编号或明确安静才完成。中断或回执丢失可能已送达的批次保留待核对，不重复发送。关闭或重配会终止旧批次；更换账号不会借新账号处理旧队列。配置接口复用原宿主登录与来源检查，令牌不进模型提示词或普通配置工具。细节见 `QQ.md`。

v0.2.2 的自主回合也可使用这些原生文件工具，保留 DSH 文件服务原有权限、先读后改与修订校验。自动创建会话使用角色文件工作区，不再使用插件运行目录。工作区配置位于“基础会话 → 回复规则与节奏 → 上下文、工作区与记忆召回”，只由管理员设置；已有会话的运行库目录经宿主 workingDirectory.set 迁移，用户自行选择的项目目录保留。
